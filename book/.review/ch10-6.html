10.6 Code Mode: 여러 도구 호출을 하나의 프로그램으로

앞 절의 Freeform은 모델이 쓴 코드를 어떻게 전달하느냐를 다뤘습니다. 이제 그 코드로 무엇을 하는지 보겠습니다. Code Mode의 본질은 여러 도구 호출을 JavaScript 코드로 재구성해, execute 한 번으로 실행하는 것입니다. 모델은 도구를 조합하고, 순서를 정하고, 독립적인 호출을 병렬로 묶습니다. 앞 결과에 따라 분기하거나 반복해서 호출하고, 받은 값을 가공하는 일까지 같은 프로그램에 적습니다.

상사가 비서에게 주는 쪽지가 달라집니다 상사(모델)가 비서(OpenCode)에게 “이슈 목록 가져와”라고 한 뒤 보고를 받고, 다시 “그중 오래된 것의 담당자를 찾아와”라고 시킬 수 있습니다. Code Mode에서는 “이슈를 가져와 → 오래된 것만 골라 → 있으면 각각 담당자를 찾아 → 번호와 담당자를 묶어 알려 줘”라는 쪽지 한 장을 줍니다. 쪽지는 설명문이 아니라 실행할 JavaScript 프로그램입니다.
  • 사용자는 평소처럼 말로 요청합니다. 쪽지를 쓰는 쪽은 모델입니다.
  • 모델은 어떤 도구를 어떻게 이어 쓸지 코드로 정해 execute에 넘깁니다.
  • OpenCode는 프로그램을 실행하고, 그 안에서 필요한 도구들을 실제로 호출합니다.
도구 호출이 사라지는 것은 아닙니다. 여러 호출을 진행하는 절차가 하나의 프로그램 안으로 들어갑니다.

실제 장면: 두 저장소의 방치된 이슈 조사하기

GitHub MCP 서버를 연결한 개발자가 TUI에서 이렇게 요청한다고 합시다.

acme/api와 acme/web에서 30일 넘게 업데이트가 없는 열린 이슈를 찾아 줘.
그런 이슈가 있는 저장소만 열린 PR도 조회해서, 이슈 번호와 PR 개수를 같이 알려 줘.

모델이 매번 다음 행동을 정한다면, 이슈 목록을 받은 뒤 날짜를 비교하고, 해당 저장소의 PR 조회를 결정해야 합니다. Code Mode에서는 그 결정 규칙까지 미리 코드에 담을 수 있습니다. 두 저장소는 서로 독립적이므로 동시에 조사하고, 각 저장소 안에서는 이슈 조회가 끝나야 PR을 조회할지 결정합니다.

아래는 모델이 execute에 보낼 수 있는 코드입니다. 이해를 돕기 위해 list_issues와 list_pulls가 조건에 맞는 전체 항목을 배열로 반환하는 설명용 MCP 도구라고 가정합니다. 실제 도구 이름·인자·반환 구조·페이지 나눔은 연결한 서버의 카탈로그를 확인해야 합니다.

모델이 작성하는 execute 프로그램 — 도구 이름과 반환 구조는 설명용const cutoff = Date.now() - 30 * 864e5 // 30일 전
const repos = ["acme/api", "acme/web"]

const results = await Promise.allSettled(repos.map(async repo => {
  // ① 순서: 이슈를 먼저 조회하고, 그 결과로 다음 행동을 정한다.
  const issues = await tools.github.list_issues({ repo, state: "open" })
  const stale = issues.filter(i => Date.parse(i.updated_at) < cutoff)

  // ② 분기: 대상이 없으면 이 저장소의 PR 조회는 생략한다.
  if (stale.length === 0) return { repo, stale: [] }

  const prs = await tools.github.list_pulls({ repo, state: "open" })
  return { repo, stale: stale.map(i => i.number), openPRs: prs.length }
})) // ③ 병렬: 두 저장소의 조사 절차를 동시에 진행한다.

// ④ 반복·가공: 성공한 결과와 실패한 저장소를 읽기 좋은 값으로 모은다.
const report = []
for (let i = 0; i < results.length; i++) {
  const result = results[i]
  report.push(result.status === "fulfilled"
    ? result.value
    : { repo: repos[i], error: String(result.reason) })
}
return report

이 프로그램에는 도구 호출을 이어 붙이는 조합, await로 정한 순서, Promise.allSettled의 병렬, if의 분기, 배열 순회와 for의 반복, filter와 map의 가공이 들어 있습니다. 모델은 이 전체 절차를 execute 한 번에 맡깁니다. 두 저장소 모두 오래된 이슈가 있으면 안쪽 도구는 네 번 호출됩니다. 한쪽에 없다면 세 번만 호출됩니다.

sequenceDiagram participant M as 상사 (모델) participant X as 비서 (OpenCode의 execute) participant T as GitHub MCP 도구 M->>X: 쪽지 한 장 (JavaScript 프로그램) par acme/api 조사 X->>T: 이슈 조회 T-->>X: 결과 X->>X: 날짜 필터링 opt 오래된 이슈가 있으면 X->>T: PR 조회 T-->>X: 결과 end and acme/web 조사 X->>T: 이슈 조회 T-->>X: 결과 X->>X: 날짜 필터링 후 필요하면 PR 조회 end X->>X: 저장소별 결과와 오류를 모음 X-->>M: 최종 반환값 (필요시 경고·로그도 전달)

그림 10-3 모델이 호출 절차를 코드로 정하고, OpenCode가 한 프로그램으로 실행합니다. 각 도구 호출은 기존 권한 검사와 훅을 거칩니다.

직접 도구 방식도 독립적인 호출을 한 번에 병렬로 요청할 수 있습니다. 따라서 차이를 “병렬 호출이 되느냐”로만 이해하면 부족합니다. Code Mode에서는 앞 결과를 보고 다음 도구를 호출할지 정하는 절차와 결과 가공까지 같은 코드에 들어갑니다. 프로그램 안에서 처리할 수 있는 판단마다 모델에게 다시 물어볼 필요가 줄어듭니다.

한 번의 execute가 성공까지 보장하지는 않습니다 안쪽 도구의 실패는 직접 호출 때와 같은 실패 문장을 가진 오류로 프로그램에 전달됩니다. 예제의 Promise.allSettled는 한 저장소가 실패해도 다른 저장소의 결과를 모읍니다. 잡지 않은 오류로 프로그램이 끝나면 모델은 오류를 읽고 코드를 고쳐 다시 호출할 수 있습니다. 중요한 호출은 반드시 await해야 합니다. 프로그램이 끝나면 아직 대기 중인 호출은 중단됩니다.

메뉴 앞면과 뒷면: 어떤 도구를 코드에서 부를까

10.2절의 메뉴를 떠올려 보십시오. 앞면은 직접 도구입니다. read·edit·shell처럼 자주 쓰는 도구는 모델이 평소대로 직접 호출합니다. 뒷면은 Code Mode 카탈로그입니다. 많은 MCP 도구와 일부 opencode.* 관리 도구는 이곳에서 찾아 쪽지에 적습니다. execute가 모든 도구를 마음대로 부르는 입구는 아닙니다. 안에서 쓸 수 있는 것은 Code Mode 카탈로그에 실리거나 search로 확인한 도구뿐입니다.

카탈로그는 시스템 지침 core/codemode로 전달됩니다. 네임스페이스별 요약 아래에 도구의 TypeScript 시그니처와 설명 첫 줄(최대 120자)이 붙습니다. 시그니처는 호출법을 알려 주는 설명이고, 모델이 실행용으로 쓰는 코드는 일반 JavaScript입니다.

카탈로그 모양 — 내용은 설명용- github (41 tools, 12 shown)
  - list_issues(input: { repo: string; state?: ... }) // List issues in a repository
  - list_pulls(input: { repo: string; ... }) // List pull requests
  ...
- jira (18 tools, none shown)
  • 처음 보여 주는 목록: INLINE_BUDGET = 2,000을 기준으로 고릅니다. 실제 토큰을 세는 대신 문자 수를 4로 나누어 비용을 추정합니다. 네임스페이스 줄과 pinned 도구는 항상 포함하고, 나머지는 네임스페이스별로 한 개씩 돌아가며 채웁니다. 따라서 2,000은 전체 목록의 엄격한 하드 상한이 아닙니다.
  • 생략된 도구 찾기: 이름을 추측하지 않고 전역 함수 search(...)로 찾습니다. 이 함수는 프로그램 관점에서 동기로 결과를 돌려줍니다. 반환된 path는 완성된 호출 표현식이므로, 모델이 확인한 경로와 시그니처를 그대로 코드에 적습니다. tools[path]로 호출하는 방식은 쓰지 않습니다.
  • 목록 변경: 서버 연결·해제 등으로 도구가 바뀌면 변경분을 전달합니다. 부분 카탈로그의 새 시그니처에는 UPDATE_BUDGET = 1,000을 나누어 씁니다. 전체 교체가 더 짧거나 도구 수가 0에서 바뀌는 경우 등에는 전체 카탈로그를 다시 보냅니다.
모델이 먼저 execute로 도구를 찾아보는 예return search({ query: "create issue", namespace: "jira", limit: 3 })

모델은 검색 결과의 path·signature·description을 확인한 뒤 실제 호출 프로그램을 작성할 수 있습니다. 도구를 탐색하는 호출이 먼저 필요할 수 있으므로, 모든 사용자 요청이 무조건 execute 한 번에 끝난다는 뜻은 아닙니다. 한 번의 실행 안에 여러 도구 호출과 처리 절차를 묶을 수 있다는 뜻입니다.

10.1절의 output과 content가 여기서 이어집니다

프로그램이 날짜를 비교하거나 항목 수를 셀 수 있는 이유는 도구 결과를 값으로 받기 때문입니다. 10.1절에서 나눈 output이 있으면 Code Mode 프로그램은 그 구조화 값을 받습니다. 없으면 content의 텍스트를 이어 붙인 문자열을 받고, 텍스트도 없으면 null을 받습니다. 그러므로 실제 반환 구조가 배열인지, 문자열인지 확인해야 위 예제처럼 정확하게 가공할 수 있습니다.

마지막 return 값은 OpenCode가 문자열 또는 간결한 JSON 텍스트로 만들어 모델에게 전달합니다. 경고와 로그가 있으면 함께 붙고, 안쪽 도구가 만든 파일도 전달될 수 있습니다. 호출 목록과 상태는 UI용 metadata로 따로 정리됩니다. 중간 원자료는 프로그램이 계산에 쓰고, 모델은 반환된 보고를 읽는 구조입니다.

컨텍스트 절약은 이 구조에서 따라오는 이점입니다
  • 중간 결과를 코드 안에서 가공합니다. 이슈 수백 개를 모델이 모두 읽는 대신, 프로그램이 골라낸 번호와 PR 개수를 받을 수 있습니다. 단, 전체 목록을 반환하거나 로그에 남기면 그만큼 다시 전달됩니다.
  • 도구 설명을 요약합니다. Code Mode 쪽 도구는 전체 JSON Schema 대신 execute 정의와 요약 카탈로그로 알립니다. 메뉴 앞면의 직접 도구 정의는 별도로 남습니다.
  • 요청 구성을 안정적으로 유지합니다. 도구 목록이 같으면 인벤토리와 execute 정의를 재사용해 프롬프트 캐시 활용에 유리하게 합니다. 전체 요청의 캐시 적중을 보장하는 것은 아닙니다.
이점의 출발점은 “결과를 짧게 줄인다”보다 넓습니다. 도구들을 엮어 처리하는 일을 프로그램에 맡기기 때문에 모델 왕복과 중간 자료 전달을 함께 줄일 수 있습니다.

실행 범위: Node.js 대신 제한된 인터프리터

쪽지를 실행하는 것은 packages/codemode의 자체 바이트코드 VM입니다. Acorn으로 JavaScript를 파싱하고 지원하는 문법만 컴파일·실행합니다. 임의의 Node.js 프로그램을 그대로 돌리는 환경은 아닙니다. TypeScript 전용 문법은 제거해 주지 않고 거부합니다.

  • 쓸 수 있는 것: 최상위 await·return, async 함수, 제너레이터, Promise 조합자, tools 트리, 전역 search, 호스트가 추가한 확장입니다. 명시적 return이 없으면 마지막 최상위 식이 결과가 됩니다. OpenCode core가 추가하는 확장은 fetch입니다.
  • 직접 쓸 수 없는 것: 파일시스템, process, 타이머(setTimeout·sleep), 임의 패키지, export입니다. OpenCode의 execute에서는 import를 이용한 외부 접근도 제공하지 않습니다. 파일을 다루려면 메뉴 앞면의 read·edit 등을 직접 호출해야 합니다.
  • 값의 경계: 도구와 프로그램 사이의 데이터는 JSON 의미론으로 복사됩니다. 호스트 객체에 마음대로 접근하는 참조를 넘기지 않습니다.
  • 하드 상한: 문자열 길이 224, 배열 길이 10,000,000, 동시에 대기하는 Promise 10,000개, 호스트와 주고받는 값의 중첩 깊이 32입니다. 타임아웃은 인터프리터 스텝 사이에서만 발동할 수 있으므로, 내장 함수 하나가 끝없이 큰 값을 만드는 것도 별도로 막습니다.
  • 내부 설계: VM·컴파일러·표준 라이브러리 등의 코어에는 effect를 import하지 않고, Effect는 호스트 경계와 실행을 연결하는 쪽에 둡니다. 라이브러리는 스냅숏으로 실행을 저장·재개할 수 있고, 호스트 호출마다 <runId>:<callId> 식별자를 유지합니다. 재개 시 이미 완료한 호출을 다시 실행하지 않도록 상태를 보존하는 기반입니다.
프로그램으로 묶어도 권한은 그대로입니다 안쪽 도구도 OpenCode의 기존 실행 경로를 거쳐 권한 검사와 훅을 적용받습니다. 메뉴에 보이는지와 실행해도 되는지는 별개입니다. Code Mode가 외부 접근 권한을 넓혀 주지는 않습니다.

켜고 끄기: 에이전트·서버·도구의 세 단위

Code Mode는 기본으로 켜져 있습니다. 일부 도구를 직접 호출하도록 바꾸거나, 에이전트 전체에서 끌 수 있습니다.

① 에이전트 단위. execute 전체에 대한 마지막 매칭 규칙이 deny이면 Code Mode가 꺼지고, 원래 Code Mode 쪽이던 도구도 직접 도구로 노출됩니다. 코드 작성이 약한 모델을 쓰는 에이전트에서 검토할 수 있습니다.

opencode.jsonc — model 값은 사용하는 모델 ID로 교체{
  "agents": {
    "quick": {
      "model": "…작은 모델…",
      "permissions": [
        { "action": "execute", "resource": "*", "effect": "deny" }
      ]
    }
  }
}

MCP 도구가 많으면 이들의 정의가 직접 도구 목록에 모두 실려 요청이 커질 수 있습니다. 다시 켜려면 이 deny 규칙을 제거하거나 적용되는 권한 규칙을 바꿉니다.

② MCP 서버 단위. mcp.servers.<name>.codemode: false로 그 서버의 도구만 메뉴 앞면에 둡니다. 도구가 몇 개뿐인 서버에 쓸 수 있습니다.

opencode.jsonc — URL과 명령은 실제 연결 값으로 교체{
  "mcp": {
    "servers": {
      "github": { "type": "remote", "url": "…" },
      "clock": { "type": "local", "command": ["…"], "codemode": false }
    }
  }
}

서버 설정의 codemode: false를 제거하면 기본 동작으로 돌아갑니다. 자체 Code Mode를 제공하는 알려진 Executor 서버(executor.sh의 해당 MCP URL이나 로컬 executor mcp)는 별도 지정이 없으면 OpenCode 쪽 Code Mode를 자동으로 끕니다. PostHog는 모드를 명시하지 않았으면 tools 모드를 요청해 서버 쪽 Code Mode를 끄고 OpenCode 쪽을 사용합니다. 사용자가 서버 설정에 codemode를 명시한 경우에는 이 자동 기본값 처리를 하지 않습니다.

③ 도구 단위. 플러그인 도구의 options에 codemode: false를 주면 직접 도구로 남습니다. skill이 그 예입니다(13장). 이 옵션을 생략하면 기본적으로 Code Mode 쪽에 들어갑니다. 다만 에이전트에서 Code Mode 전체를 껐다면 직접 도구로 노출됩니다.

플러그인 도구 정의의 옵션 부분options: { codemode: false }

HTTP API도 코드에 엮을 수 있습니다. Code Mode 도구가 있는 환경에서 사용자가 “npm의 react와 vue 최신 버전을 함께 확인해 줘”라고 하면, 모델은 다음처럼 두 HTTP 요청과 필요한 필드 추출을 한 프로그램으로 만들 수 있습니다.

execute 안에서 HTTP 요청을 병렬로 묶는 예const packages = ["react", "vue"]
const results = await Promise.allSettled(packages.map(async name => {
  const response = await fetch("https://registry.npmjs.org/" + name + "/latest")
  if (!response.ok) throw new Error(name + ": HTTP " + response.status)
  const data = await response.json()
  return { name, version: data.version }
}))
return results.map((r, i) => r.status === "fulfilled"
  ? r.value
  : { name: packages[i], error: String(r.reason) })

상사가 한 건씩 전화로 지시하던 일을, 비서가 실행할 쪽지 한 장으로 엮습니다. Code Mode에서는 여러 도구 호출과 그 사이의 처리 절차가 하나의 프로그램이 됩니다.

  • 권한: 첫 URL은 webfetch와 같은 권한으로 검사합니다. ask이면 여기서도 확인합니다. 리다이렉트의 각 목적지에서는 deny 규칙을 다시 검사합니다.
  • URL: file:과 URL 안의 자격 증명을 거부합니다. 리다이렉트 목적지는 HTTP/HTTPS만 허용하며 URL 안의 자격 증명도 거부합니다.
  • 시간과 횟수: 30초 타임아웃을 두고 리다이렉트는 최대 20회까지 직접 추적합니다. 실행 중단에도 연동합니다.
  • 자격 정보 보호: 다른 출처(origin)로 이동하면 authorization·cookie·proxy-authorization 헤더를 제거합니다.

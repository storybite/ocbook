부록 A 슬래시 명령 총람

TUI의 내장 슬래시 명령을 한곳에 모았습니다. 각 명령은 한 줄 설명과 함께, 그 명령이 생겨난 원리와 실제 사용 예가 있는 본문의 🛠 상자로 링크됩니다. 본문에 마땅한 자리가 없는 명령은 A.2절에서 자세히 설명합니다. 키 표기에서 ctrl+x u는 리더 키 ctrl+x를 누르고 뗀 뒤 u를 누른다는 뜻입니다.

A.1 내장 명령 한눈에 보기

프롬프트 맨 앞에서 /를 치면 아래 명령과 서버 명령(/init, /review, MCP 프롬프트, 내가 만든 명령)이 가나다순으로 섞여 나옵니다(13.6 슬래시 명령 찾기). "세션 화면"이라고 적은 명령은 세션을 연 상태에서만 동작합니다.

A.2 본문에서 다루지 않은 명령

원리 장에 붙이기에는 작지만, 알아 두면 손이 덜 가는 명령들입니다.

/copy — 마지막 답변 복사 (ctrl+x y)

가장 최근 assistant 메시지의 글(text) 부분만 줄바꿈으로 이어 클립보드에 넣습니다. 생각 과정과 도구 출력은 빠집니다. 그보다 새로운 압축 요약이 있으면 그 요약을 복사합니다.

예. 에이전트가 "변경 요약"을 마지막에 정리해 주었다면 ctrl+x y 한 번으로 PR 설명란에 붙여 넣을 수 있습니다.

주의. 여기서 "메시지 하나"는 모델 호출 한 번(스텝 하나, 8.1절)입니다. 마지막 스텝이 도구 호출뿐이었다면 "No text content found in last assistant message"가 뜨고, 같은 턴의 앞 스텝에 있던 글은 함께 복사되지 않습니다. 대화 전체가 필요하면 명령 팔레트(ctrl+p)의 "Copy session transcript"(생각 과정 포함 Markdown)를, 세션 ID가 필요하면 "Copy session ID"를 쓰십시오.

/export — 대화 기록 내보내기 (ctrl+x x)

옵션 대화상자에서 형식과 내용을 고릅니다.

형식옵션(기본값)결과
MarkdownThinking(포함), Tools(포함)제목·ID·날짜 머리말 아래 User, Shell, Assistant 절. 합성 메시지와 압축 메시지는 빠짐
JSONSanitize(끔)정착된 메시지 전체. Sanitize를 켜면 글·제목·경로·파일 내용이 [redacted:종류:id]로 바뀌어 구조만 남음

Enter를 누르면 현재 폴더에 session-<무작위 UUID>.md(또는 .json)로 저장하고 경로를 보여 줍니다(c로 경로 복사). 클립보드로 바로 복사할 수도 있습니다. 파일 이름이 세션 제목이 아니라 매번 새 UUID라는 점에 유의하십시오.

예 1 — 동료에게 작업 과정 공유. Markdown에 Tools를 끄고 내보내면, 도구 출력 없이 질문과 답만 담긴 읽기 좋은 문서가 됩니다.

예 2 — 버그 제보에 구조만 첨부. JSON에 Sanitize를 켜면 코드와 경로가 가려지므로, 어떤 순서로 무엇이 오갔는지만 개발자에게 보여 줄 수 있습니다.

주의. 내보내기는 되돌리기 상태를 거르지 않는 것으로 보입니다. /undo로 숨겼지만 아직 확정하지 않은 메시지가 들어갈 수 있으므로, 깔끔한 기록이 필요하면 확정한 뒤 내보내십시오.

/editor — 외부 편집기로 프롬프트 쓰기 (ctrl+x e)

지금 프롬프트 칸의 내용(붙여 넣은 긴 글 포함)을 파일로 꺼내 외부 편집기로 엽니다. 편집기를 닫으면 그 내용이 프롬프트 칸을 대신하고, @ 멘션 강조도 다시 맞춰집니다. 서버에는 아무것도 보내지 않습니다. 보낼지는 돌아와서 정합니다.

편집기는 환경 변수 $VISUAL, 없으면 $EDITOR로 정합니다. 둘 다 없으면 "Failed to open editor"가 뜹니다. VS Code를 쓴다면 창을 닫을 때까지 기다리도록 --wait을 붙여야 합니다.

# macOS·Linux (~/.zshrc 등)
export EDITOR="code --wait"

# Windows PowerShell ($PROFILE)
$env:EDITOR = "code --wait"

예. 요구 사항이 열 줄이 넘는 작업 지시, 표나 코드 조각이 섞인 프롬프트는 TUI 입력 칸보다 편집기에서 쓰는 편이 훨씬 편합니다.

/help — 무엇이든 ctrl+p

/help는 한 줄만 보여 줍니다. "어디서든 ctrl+p를 누르면 쓸 수 있는 모든 동작과 명령이 보인다." 명령 팔레트에는 슬래시 이름이 없는 동작(예: "Copy session transcript", 탭 다시 열기)까지 들어 있고, 각 동작의 단축키도 함께 보입니다. 명령 이름이 기억나지 않을 때는 슬래시 목록보다 팔레트가 빠릅니다.

/exit — TUI 끝내기 (/quit, /q, ctrl+c, ctrl+d)

TUI 화면을 닫습니다. ctrl+c와 ctrl+d는 프롬프트 칸이 비어 있거나 포커스가 없을 때만 종료로 동작하므로, 쓰던 글이 실수로 날아가지 않습니다. 슬래시 없이 exit, quit, :q만 치고 Enter를 눌러도 종료됩니다.

가장 중요한 점은 TUI를 끝내도 서버의 작업은 계속된다는 것입니다. 맡겨 둔 일은 백그라운드 서버에서 이어지고, 다시 열어 /sessions로 확인하면 됩니다(7.6 TUI를 닫아도 일은 계속된다).

/debug — 진단 정보

버전(채널), 날짜, OS, 터미널, 세션 ID, 모델을 보여 줍니다. Enter를 누르면 전부 클립보드에 복사됩니다("Debug info copied"). 버그를 제보할 때 이 내용을 그대로 붙이면 재현에 필요한 환경 정보가 한 번에 전달됩니다. 이름이 비슷한 "Toggle debug panel"(슬래시 이름 없음)은 별개의 기능입니다.

/highlights — 새 기능 보기

"What's new in <버전>" 창에 이번 버전의 주요 변경을 보여 줍니다(↑/↓, j/k, PgUp/PgDn으로 스크롤). 업데이트한 뒤 처음 시작할 때, 홈 화면이 한가하면 한 번 자동으로 뜹니다. 이 자동 표시는 /settings의 "Release highlights"로 끌 수 있습니다. 빌드에 하이라이트가 없으면 명령이 보이지 않습니다.

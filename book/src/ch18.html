18장 CLI·클라이언트·SDK로 직접 만들기

지금까지 내부를 봤다면 이제 바깥에서 OpenCode를 다루는 세 가지 방법을 봅니다. 명령줄(CLI), 원격 클라이언트(@opencode/client), 프로세스 안에 품는 SDK(@opencode/sdk)입니다. 마지막에는 SDK로 작은 리뷰 봇을 만들어 봅니다.

SDK가 클라이언트를 "재사용"하는 이유 SDK 내부는 OpenCode.make({ baseUrl: "http://opencode.local", fetch: host.fetch })입니다. 즉 메모리 속 라우터를 가리키는 클라이언트일 뿐입니다. 덕분에 원격 클라이언트·임베디드 호스트·플러그인이 같은 메서드 이름, 같은 오류, 같은 스트림 타입을 씁니다. 로컬에서 SDK로 프로토타입한 코드를 서버 연결로 바꿀 때 거의 고칠 것이 없습니다.

18.3 @opencode/client로 원격 서버 다루기

client.tsimport { OpenCode } from "@opencode/client"
import { Service } from "@opencode/client/service"   // Node 전용

const endpoint = await Service.ensure()               // 로컬 백그라운드 서비스 확보
const client = OpenCode.make({ baseUrl: endpoint.url, headers: Service.headers(endpoint) })

const session = await client.session.create({ location: { directory: process.cwd() } })

// 1) 구독을 먼저 시작해야 합니다. iterable은 첫 next()에서야 연결을 엽니다.
//    server.connected는 types 필터와 무관하게 항상 먼저 전달됩니다(shared-events.ts).
const events = client.event.subscribe({ types: ["session.step.ended"] })[Symbol.asyncIterator]()
await events.next()                                   // server.connected 수신 = 연결 완료

// 2) 그다음 프롬프트를 보냅니다.
await client.session.prompt({ sessionID: session.id, text: "README를 요약해 줘" })

for (let r = await events.next(); !r.done; r = await events.next()) {
  if (r.value.data?.sessionID === session.id) console.log(r.value.type, r.value.data)
}

공식 문서 services/site/src/docs/content/build/client/index.mdx의 예시(Service.ensure, Service.headers, session.create/prompt, event.subscribe({types}))를 조합한 코드입니다.

  • 이벤트 구독은 실시간 전용입니다. 재생도 자동 재연결도 없으므로, 프롬프트를 보낸 뒤에 구독을 시작하면 그사이 끝난 실행을 놓칩니다. 누락 없이 관찰하려면 영속 로그 client.experimental.session.log({ sessionID, after, follow: true })를 쓰십시오(6.4절).
  • 네이티브·RPC 구독자는 하나의 지연 연결을 공유하고, 늦게 붙은 구독자는 server.connected를 받습니다.
  • 플러그인 RPC: 플러그인의 ./rpc 계약을 import해 client.rpc(Def)로 호출합니다.

18.4 @opencode/sdk로 임베딩

packages/sdk/README.md 기반import { OpenCode } from "@opencode/sdk"

await using opencode = await OpenCode.create({
  plugins: [myPlugin],
  database: { path: "./sessions.db" },   // 기본은 ":memory:"
})
const session = await opencode.sessions.create({ location: { directory: "/workspace" } })
await opencode.sessions.prompt({ sessionID: session.id, text: "Review the changes" })
  • 기본 DB는 메모리입니다. 재시작 복구(SessionRestart)를 쓰려면 파일 경로가 필요합니다.
  • 세션 선택 플러그인(instances: { key(session), configure(key) }): 예컨대 Slack 스레드마다 다른 플러그인 집합. README는 이것이 "권한이나 저장소 격리 경계가 아니다"라고 경고합니다.
  • Cloudflare workerd: OpenCodeWorkerd.create({ storage: state.storage, config, plugins })로 Durable Object 안에서 실행합니다.
  • 플러그인 순서: SDK·인스턴스 플러그인은 내장 플러그인 뒤 pre 그룹에 들어가며, 설정으로 ID를 지정해 끌 수 있습니다.

18.5 실습: PR 리뷰 봇 설계

지금까지 배운 것을 조합해 "PR이 열리면 보안 리뷰를 남기는 봇"을 설계해 봅니다.

그림 18-2 SDK 기반 리뷰 봇의 흐름

  1. 에이전트: 플러그인에서 ctx.agent.transform으로 reviewer를 정의합니다. 기본 권한이 전체 허용이므로 edit: * deny, shell: * deny를 먼저 두고 그 뒤에 git diff *, git log * allow를 덧붙입니다(12.3절, 11장).
  2. 격리: PR마다 워크트리를 만들고 그 디렉터리를 Location으로 세션을 만듭니다. Location이 다르면 설정·도구·권한 그래프도 따로 컴파일됩니다(5장).
  3. 명령 실행: prompt에 "/review pr" 문자열을 넣으면 그냥 텍스트로 접수됩니다. 슬래시 명령은 별도 API session.command({ sessionID, name: "review", text: "pr" })(POST /api/session/:id/command)로 실행합니다(13.6절).
  4. 무인 실행: 사람이 없으므로 ask가 생기면 막힙니다. 권한을 명시적으로 allow/deny만 쓰게 설계하거나, 무인(Unattended) 컨텍스트에서 ask가 deny로 정착되는 점을 이용합니다(11.2절).
  5. 완료 감지: session.step.ended와 세션 유휴 이벤트를 구독하거나 session.wait를 씁니다.
  6. 내구성: DB를 파일로 두면 봇이 재시작돼도 진행 중이던 리뷰가 클레임을 통해 재개됩니다(7.6절).
  7. 비용: 같은 저장소의 PR이 이어지면 프롬프트 캐시가 적중하도록 warming이나 cache.ttl: "1h"를 검토합니다(9장, 17장).

13장 스킬·명령·지침 파일

모델에게 "무엇을 알고, 어떻게 일할지"를 알려 주는 수단은 세 가지입니다. 항상 실리는 지침(AGENTS.md), 필요할 때만 불러오는 스킬, 사람이 호출하는 슬래시 명령입니다. 셋은 언제 컨텍스트에 들어가는지가 다릅니다.

그림 13-1 점진적 공개(progressive disclosure)

왜 스킬을 "목록만" 싣나요? 스킬 스무 개의 본문을 모두 실으면 매 요청 수만 토큰이 낭비되고, 관련 없는 지시가 모델을 산만하게 합니다. 설명 한 줄씩만 보여 주고 모델이 "지금 이 작업에 필요하다"고 판단할 때 본문을 불러오게 하면, 컨텍스트는 작게 유지하면서 지식은 무한히 늘릴 수 있습니다.

그림 13-2 위로 걸어 올라가며 AGENTS.md 수집

  • 전역: ~/.config/opencode/AGENTS.md(또는 $OPENCODE_CONFIG_DIR/AGENTS.md).
  • 프로젝트: 작업 디렉터리부터 위로. 작업 디렉터리가 HOME 아래면 HOME에서, 아니면 프로젝트 루트에서 멈춥니다. 가까운 것부터 정렬.
  • 설정: instructions: string[] — 절대 경로/glob, ~/, 상위로 찾는 상대 glob, http(s) URL(5초 타임아웃, 설정 리로드 시에만 가져오고 실패하면 마지막 정상본 유지).
  • 순서: 전역 → 프로젝트(가까운 것→먼 것) → 설정.
  • 렌더링: "Instructions from: <path>\n<content>". 모든 후보 파일을 100ms 디바운스로 감시합니다.
CLAUDE.md는 읽지 않습니다 V1은 프로젝트에서 AGENTS.md → CLAUDE.md → CONTEXT.md(폐기 예정) 순으로 찾고 ~/.claude/CLAUDE.md도 읽었습니다. V2는 AGENTS.md만 찾습니다. 마이그레이션 문서는 CLAUDE.md 내용을 AGENTS.md로 옮기고 "호환성 이슈를 제보하라"고 안내합니다. 즉 의도된 단절이라기보다 인정된 간극입니다. .claude/ 디렉터리는 스킬 탐색에만 쓰입니다.

하위 디렉터리 AGENTS.md의 지연 주입

read 도구가 성공하면, 읽은 파일의 디렉터리에서 Location 루트(제외)까지 올라가며 AGENTS.md를 찾아 영속 합성 메시지로 주입합니다. 메타데이터 instruction.paths가 유일한 장부여서, 압축이나 되돌리기로 그 메시지가 사라지면 다시 주입됩니다.

왜 하위 AGENTS.md는 "나중에"일까요? 모노레포에는 패키지마다 AGENTS.md가 있을 수 있습니다. 시작할 때 전부 실으면 작업과 무관한 규칙이 컨텍스트를 채웁니다. 모델이 실제로 그 디렉터리의 파일을 읽는 순간 그 지역 규칙을 주입하면, 필요한 규칙이 필요한 때 정확히 도착합니다.

13.3 SKILL.md 형식

.opencode/skills/release-notes/SKILL.md---
name: Release notes
description: CHANGELOG 항목을 작성하거나 릴리스 노트를 만들 때 사용
metadata:
  opencode/autoinvoke: true
# disable-model-invocation: true   # 모델 자동 호출 금지(사용자만)
---
1. `git log` 로 직전 태그 이후 커밋을 모읍니다.
2. scripts/group.py 로 분류합니다.
...
항목규칙
ID스킬의 고유 이름입니다. SKILL.md가 든 폴더 이름을 씁니다. 스킬 폴더 바로 아래에 foo.md 파일 하나만 두면 foo가 ID입니다.
name화면에 보이는 이름입니다. frontmatter에 name이 있으면 그 값, 없으면 ID를 씁니다.
autoinvoke
(자동 사용)		켜 두면 모델이 필요할 때 이 스킬을 알아서 꺼내 씁니다. 꺼 두면 사용자가 직접 부를 때만 씁니다. 아무것도 적지 않으면 켜집니다.
스캔얕은 폴더부터 6단계 깊이까지 찾고, 숨김·무시 폴더는 건너뜁니다. SKILL.md를 찾은 폴더 아래는 더 뒤지지 않습니다.

각 규칙을 조금 더 풀면 다음과 같습니다.

  • ID: 스킬의 고유 이름은 SKILL.md가 들어 있는 폴더 이름입니다. 스킬 폴더 바로 아래에 foo.md처럼 파일 하나만 두면 파일 이름 foo가 ID가 됩니다.
  • name: 화면에 보이는 이름입니다. frontmatter에 name을 적으면 그 값을 쓰고, 없으면 ID를 씁니다.
  • autoinvoke(자동 사용): SKILL.md 맨 위의 --- 두 줄 사이에서, metadata 아래에 opencode/autoinvoke: true를 적으면 켜지고 false를 적으면 꺼집니다. 이 설정이 없을 때는 disable-model-invocation: true를 적어도 꺼집니다. 둘 다 적지 않으면 켜집니다.
  • 스캔: 스킬 폴더는 가까운(얕은) 폴더부터 차례로 뒤지되 6단계 깊이까지만 내려갑니다. 숨김 폴더와 무시 대상 폴더는 건너뜁니다. 어떤 폴더에서 SKILL.md를 찾으면 그 폴더를 스킬 하나로 보고 그 아래 폴더는 더 뒤지지 않습니다.

13.5 스킬이 모델에게 보이는 방식

스킬은 도구 설명이 아니라 지침 블록(core/skill-guidance)으로 광고됩니다. 권한상 skill:<id>가 거부되지 않고, 설명이 있으며, autoinvoke가 false가 아닌 것만 실립니다.

skill/instructions.ts (요약)Skills provide specialized instructions and workflows for specific tasks.
Use the skill tool to load a skill when a task matches its description.
<available_skills>
  <skill><id>release-notes</id><name>Release notes</name><description>…</description></skill>
</available_skills>

지침 소스이므로 변경은 델타로 전달됩니다("새 스킬이 생겼습니다…", "다음 스킬 ID는 더 이상 쓰지 마십시오…").

skill 도구의 결과<skill_content name="Release notes">
# Skill: Release notes
…본문…
Base directory for this skill: /repo/.opencode/skills/release-notes
Relative paths in this skill (e.g., scripts/, reference/) are relative to this base directory.
<skill_files><file>scripts/group.py</file>…(최대 10개)</skill_files>
</skill_content>

skill 도구는 항상 직접 도구(codemode: false)이며 권한 skill을 스킬 ID로 검사합니다. 사용자가 스킬을 직접 지정하면 같은 <skill_content> 모양이 프롬프트에 주입됩니다. 조직 정책 skill.use로 특정 스킬을 막을 수 있습니다.

이렇게 씁니다 — 스킬을 직접 불러 쓰기: /skills · @

스킬은 보통 모델이 설명(description)을 보고 필요할 때 스스로 불러옵니다. 하지만 "이번에는 이 절차를 꼭 따라라"라고 지정하고 싶을 때가 있습니다. @스킬이름으로 스킬을 직접 지정하는 기능은 V2에서 지원하며, 이 책에서 비교하는 V1(1.19.5)에는 없습니다.

  1. /skills를 입력하면 현재 위치에서 쓸 수 있는 스킬 목록(이름과 설명)이 뜹니다.
  2. 하나를 고르면 즉시 실행되는 것이 아니라, 커서 위치에 강조된 @스킬이름이 들어갑니다. 프롬프트 칸에서 @를 쳐서 고를 수도 있습니다.
  3. 나머지 요청을 이어 쓰고 보냅니다. 보내는 순간 서버가 스킬 본문을 읽어 이 사용자 메시지 앞에 붙여 모델에게 전달합니다.

예. release-notes 스킬이 있다면 @release-notes v2.3.0 태그 이후 변경으로 릴리스 노트 써 줘처럼 보냅니다. 모델이 스킬을 찾아 읽는 단계를 건너뛰고 처음부터 그 절차대로 일합니다. 스킬 본문이 그 메시지에 통째로 들어가므로, 긴 스킬을 매번 붙이면 토큰이 그만큼 늘어난다는 점도 기억하십시오.

13.6 슬래시 명령

코어에서 명령은 데이터가 아니라 코드입니다: {name, description?, execute(invocation)}. 설정 명령은 이 인터페이스를 템플릿 확장으로 구현한 것입니다.

종류내용
내장 /init가이드에 따라 AGENTS.md 작성(기존 CLAUDE.md, .cursor/rules/ 등을 참고)
내장 /review변경 리뷰 [commit|branch|pr], 기본은 커밋되지 않은 변경
MCP 프롬프트<server>:<prompt>로 자동 등록, 위치 인자를 선언된 arguments에 순서대로 매핑
사용자 정의commands 설정 키 또는 {command,commands}/**/*.md
.opencode/commands/fix-issue.md → /fix-issue 123 "로그인 실패"---
description: 이슈를 재현하고 수정
agent: build
model: openai/gpt-5.5#medium
subagent: false
---
GitHub 이슈 #$1 을 처리합니다. 요약: $2
현재 브랜치: !`git branch --show-current`
  • $ARGUMENTS: 입력 전체. $1…$N: 위치 인자(따옴표·[Image N] 인식). 가장 큰 번호가 나머지를 모두 삼킵니다.
  • !`cmd`: 셸 출력으로 치환(Location 디렉터리, 동시 최대 2개).
  • 자리표시자가 없으면 입력을 빈 줄 뒤에 덧붙입니다.
  • subagent: true이거나 대상 에이전트가 subagent 모드면 자식 세션에서 실행. 아니면 에이전트·모델을 바꾼 뒤 같은 세션에 프롬프트(기본 전달 steer).
이렇게 씁니다 — 슬래시 명령 찾기와 내 명령 만들기

프롬프트 칸의 맨 앞에서 /를 치면 자동 완성 목록이 열립니다. 이 목록에는 두 출처가 섞여 있습니다.

  • TUI 내장 명령: /new, /undo, /worktrees 같은 화면 조작 명령. 별칭도 각각 한 줄씩 나옵니다(/sessions, /resume, /continue).
  • 서버 명령: 위 표의 /init, /review, MCP 프롬프트(서버:프롬프트), 그리고 내가 만든 명령.

둘은 구분 없이 가나다(알파벳)순으로 섞이고, 입력한 글자로 흐릿하게(fuzzy) 걸러 최대 10개를 보여 줍니다. 앞글자가 일치하는 항목이 위로 올라옵니다. 스킬은 이 목록이 아니라 @ 목록에 있습니다. 명령 이름이 기억나지 않으면 ctrl+p로 명령 팔레트를 여십시오. 슬래시 이름이 없는 동작까지 모두 검색됩니다.

인자를 받는 명령(/cd, /rename, /btw와 내가 만든 명령)은 목록에서 고르면 /이름 까지만 넣어 주므로 뒤에 인자를 이어 쓰면 됩니다. 인자가 없는 내장 명령은 고르는 즉시 실행됩니다.

예 — 매번 치는 지시를 명령으로 만들기. PR을 올리기 전에 늘 "변경을 검토하고, 테스트를 돌리고, 커밋 메시지를 제안해"라고 쓴다면 .opencode/commands/ship.md를 만듭니다.

---
description: PR 올리기 전 점검
agent: build
---
현재 변경을 검토하고 테스트를 실행한 뒤, 문제가 없으면 커밋 메시지를 제안합니다.
특히 확인할 점: $ARGUMENTS
현재 브랜치: !`git branch --show-current`

이제 /ship 결제 모듈의 예외 처리라고 보내면 $ARGUMENTS 자리에 "결제 모듈의 예외 처리"가 들어가고, !`…` 자리는 셸 실행 결과로 바뀐 뒤 프롬프트로 접수됩니다. 새 명령 파일을 만든 뒤 목록에 안 보이면 /reload(4.3절)를 하십시오.

전체 내장 명령의 목록과 짧은 설명은 부록 A에 있습니다.

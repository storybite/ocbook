# 책 집필 지시서

이 파일 하나를 프롬프트로 주어 책을 만든다.

- **1부(책의 방향성)만 책마다 새로 쓴다.**
- **2부(제작 규칙)는 고치지 않는다.** 이 저장소의 bookbot 엔진 위에서 그대로 돌아가고, 『OpenCode V2 해부』와 같은 디자인·구성이 나오게 하는 고정 규칙이다.
- 1부와 2부가 부딪히면 2부의 형식·디자인 규칙이 우선이고, 내용의 방향은 1부를 따른다.

# 2부. 제작 규칙 (고정 — 책마다 고치지 않음)

## 2.1 새 책을 시작할 때 (이 저장소를 복사한 직후)

이 저장소는 **엔진**(`bookbot/`, `pyproject.toml`, `README.md`, `FORMAT.md`)과 **책**(`book/`)으로 나뉜다. 엔진은 그대로 두고 책만 새로 채운다.

| 대상 | 처리 |
|---|---|
| `.git/` | 지우고 `git init`으로 새로 시작한다(앞 책의 이력을 가져가지 않는다) |
| `book/.bookbot/` | 지운다. 앞 책의 대화·사용량·수정 기록·업로드 이미지·색인이다 |
| `book/src/` 안의 모든 파일 | 지운다(앞 책의 원고와 그 책 전용 파일). 새 원고를 여기에 쓴다 |
| `book/<앞 책>.html`, `book/review/`, `book/.review/` | 지운다 |
| `book/directions.md` (이 파일) | 1부만 새 책의 방향성으로 바꿔 쓴다. 2부는 그대로 둔다 |
| `book/book.toml` | 새 책에 맞게 다시 쓴다(2.3) |
| `book/README.md` | 새 책에 맞게 다시 쓴다(책 소개, 실행법, 폴더 표, 참조 소스) |
| 루트 `CLAUDE.md` | 앞 책 전용 내용(참조 소스 위치 등)을 새 책 것으로 바꾼다. "책 챗봇 엔진" 절은 남긴다 |
| 루트 `README.md` | 첫 줄 제목과 폴더 그림의 책 이름만 바꾼다 |
| `bookbot/`, `pyproject.toml`, `FORMAT.md`, `.gitignore` | 그대로 둔다 |

**명령은 늘 저장소 루트에서, 책 폴더를 인자로 준다.**

```bash
python -m bookbot build book      # 원고 → 책 HTML → 챗봇 색인
python -m bookbot serve book      # http://127.0.0.1:<port>/
```

- 루트에서 실행해야 이 복사본의 엔진을 쓴다.
- `book/` 안에서 그냥 `python -m bookbot`을 부르면, 다른 저장소에서 `pip install -e .`로 설치해 둔 엔진이 대신 불린다.
- 복사본에서는 `pip install -e .`를 하지 않는다. 하면 전역 `bookbot`이 이 복사본으로 바뀌어, 다른 책들도 이 엔진으로 돌게 된다.

## 2.2 결과물과 디자인

- 결과물은 `book/` 아래에 둔다. 원고는 `book/src/chNN.html`에 쓰고, 엔진이 이를 `book/<output>.html` 한 파일로 조립한다. 책 HTML을 손으로 쓰거나 고치지 않는다(빌드하면 덮어쓴다).
- 다음은 모두 엔진 템플릿이 준다. 원고에 CSS·스크립트·레이아웃을 넣지 않는다.
  - 왼쪽 사이드바 목차(장·절)와 목차 검색
  - 장 단위 표시, 이전/다음 이동, 밝은/어두운 테마
  - mermaid 렌더링, 본문 클릭 챗봇
- `book/src/template.html`을 두지 않는다. 엔진 템플릿을 그대로 써야 모든 책의 디자인이 같다.

## 2.3 book.toml

```toml
id = "영소문자-id"                 # 브라우저 저장 키·API 의 책 id. 다른 책과 겹치지 않게
title = "책 제목"
subtitle = "목차 위 한 줄 부제"
output = "<id>.html"
port = 8772                        # 다른 책과 겹치지 않게 (『OpenCode V2 해부』 = 8771)

[prompt]
intro = """당신은 『책 제목』이라는 책에 대해 묻고 답하는 조수입니다.
이 책은 …을 다룹니다.
다루는 내용: (장 주제를 쉼표로 나열)
웹 검색 출처: (공식 저장소·공식 문서 주소. 믿지 말아야 할 옛 주소가 있으면 함께)"""
topics = "웹 검색을 허용할 주제를 쉼표로 (책 주제와 관련 기술)"
style = "합쇼체, 원리 중심 설명"
cite_example = "[3.2 실제 절 제목](#ch03-2)"   # 이 책의 실제 절 하나

# 1부의 참조 자료에 로컬 소스 저장소가 있을 때만 쓴다. 없으면 [sources] 를 통째로 뺀다
[sources]
name = "소스 이름"
tool_prefix = "영소문자"           # → <prefix>_search · <prefix>_read
[[sources.repo]]
id = "v1"
label = "이름 버전"
root = 'D:\경로\repo'
```

- `[sources]`의 `rules`·`edit_rules`는 비워 두면 엔진 기본 문안을 쓴다. 버전 비교처럼 책에 특별한 소스 규칙이 있을 때만 쓴다.
- 키의 자세한 뜻은 루트 `README.md`의 "book.toml"에 있다.

## 2.4 원고 형식

자세한 형식은 루트 `FORMAT.md`를 따른다. 핵심은 다음과 같다.

- **장:** 장 하나 = `book/src/chNN.html` 한 파일(`ch01`, `ch02`, …). 파일 이름 순서가 책 순서다.
  ```html
  <section class="chapter" id="ch03">
  <h1><span class="num">3장</span> 장 제목</h1>
  <p class="lead">이 장에서 무엇을, 왜 다루는지 1~2문장</p>
  <h2 id="ch03-1">3.1 절 제목</h2>
  …
  </section>
  ```
- **절:** `<h2 id="chNN-M">N.M 제목</h2>`. 소절은 id 없는 `<h3>`를 쓴다.
- **부록:** 파일 번호는 이어서 쓰고(`ch12.html`), 장 id는 `appA`·`appB`로 한다.
  - 제목은 `<span class="num">부록 A</span>`, 절은 `<h2 id="appA-1">A.1 …</h2>`.
- **id:** 책 전체에서 한 번만 쓴다. 한번 붙인 id는 바꾸지 않는다(링크·챗봇 기록이 걸린다).

## 2.5 디자인·서술 관례 (『OpenCode V2 해부』와 같게)

- **문체:** 합쇼체(…합니다).
- **1장:** 책이 다루는 문제와 핵심 개념을 소개하고, 다음 두 절을 둔다.
  - "N.M 이 책의 구성" — 장 지도
  - "N.M 근거와 표기 규칙" — 기준 자료와 버전·커밋, 상자 색의 뜻
- **마지막 장:** 정리와 더 읽을거리("맺으며"). 레퍼런스 표가 필요하면 부록에 둔다.
- **상자 4종**

| 상자 | 제목 | 쓰임 |
|---|---|---|
| `<div class="box why">` | "왜 …일까요?" 같은 질문형, 또는 "…의 원리" | 설계 이유·원리 (초록) |
| `<div class="box note">` | `참고` | 보충 설명 (파랑) |
| `<div class="box warn">` | `주의` | 함정, 문서와 실제의 불일치 (노랑) |
| `<div class="box use" id="use-<이름>">` | `이렇게 씁니다 — <주제>` | 원리에서 나온 실제 사용법 (아래) |

  - 상자 제목은 `<b>…</b>`로 상자 첫머리에 쓴다.
  - "이렇게 씁니다" 상자에는 언제·왜 쓰는지, `<p><b>예 1 — 상황</b> …</p>` 형태의 구체적 예, 원리에서 나오는 요령과 함정을 담는다.
- **그림:** 장·절마다 흐름·구조를 mermaid로 그린다(`flowchart`, `sequenceDiagram` 등).
  - 노드 라벨은 `A["라벨"]`처럼 큰따옴표로 감싸고, 줄바꿈은 `<br/>`로 한다. 라벨 안에는 큰따옴표를 쓰지 않는다.
  - 그림 바로 뒤에 `<p class="cap">그림 N-M 설명</p>`을 단다. 번호는 장마다 1부터 매긴다.
- **코드:** `<pre><code><span class="src">경로 — 함수 (요약)</span>…</code></pre>`처럼 짧게 발췌한다.
  - 줄였으면 `(요약)`을 붙이고, 생략한 곳은 `...`로 표시한다.
  - 직접 확인한 코드만 싣는다.
- **표:** 비교와 설정 목록에 쓴다. 첫 행은 `<th>`로 쓴다.
- **상호 참조:** 다른 절은 `<a href="#ch09-1">9.1 절 제목</a>`으로 건다.
- **인라인 `style`:** 쓰지 않는다. 예외는 1장의 상자 색 안내 문구(`style="color:var(--why-line)"` 등) 하나다.

## 2.6 집필 원칙

- **목표:** 레퍼런스가 아니라, 원리를 이해하고 그 위에서 **제대로 쓰게** 하는 것이다.
  - 기능·명령·설정은 별도 목록으로 떼어 두지 않는다. 그 원리를 설명하는 장 안의 "이렇게 씁니다" 상자로 엮는다.
  - 레퍼런스 표는 보조로만 쓴다(부록).
- **근거:** 사실·코드·버전은 1부의 참조 자료(로컬 소스, 공식 문서)로 직접 확인한 것만 쓴다.
  - 확인하지 못한 것은 쓰지 않거나, 확인하지 못했다고 밝힌다.
  - 문서와 실제 코드가 다르면 코드를 따르고, `주의` 상자로 표시한다.
- **기준 버전:** 다루는 대상의 기준 버전(가능하면 커밋까지)을 1장에 적고, 책 전체를 그 버전에 맞춘다.

## 2.7 빌드와 검증 (장을 쓰거나 고칠 때마다)

1. `python -m bookbot build book`을 실행한다. 중복 id 등으로 실패하면 고친다.
2. `python -m bookbot serve book`을 띄우고 브라우저에서 확인한다.
   - 목차의 장·절
   - 그림(mermaid 문법 오류가 없는지)
   - 본문 블록을 클릭하면 챗 창이 열리는지
3. 챗봇에 질문을 한두 개 해 본다.
   - 책 절을 읽고(`read`) 답하는지 본다.
   - `[sources]`가 있으면 소스 검색·읽기 도구도 쓰는지 본다.
4. 시험으로 만든 대화는 챗 창의 이력 메뉴에서 지운다.
   - 사용량 패널의 [초기화]는 시험분만이 아니라 **누적 기록 전체**를 지운다.
   - 그러므로 [초기화]는 실제로 쓴 기록이 아직 없는 새 책에서만 쓴다.

## 2.8 하지 말 것

- 책 때문에 엔진(`bookbot/`)이나 `FORMAT.md`를 고치지 않는다. 엔진을 바꾸면 이 엔진을 쓰는 모든 책에 영향이 간다. 꼭 필요하면 따로 판단한다.
- 원고에 `<script>`, `on…=` 이벤트 속성, `<style>`·`<link>`·`<iframe>`을 넣지 않는다.
- 기존 id를 바꾸거나 지우지 않는다.
